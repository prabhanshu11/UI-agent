What is this page

These are 64x64 grayscale patches extracted around where the system thinks the cursor is. Each patch is fed through TinyCursorNet (14K param CNN) to classify: cursor or not cursor.

Your job: review samples the CNN gets wrong, tag features, and retrain. The CNN improves only from data you label here.
  • OK — CNN's label is correct for this patch
  • X (Wrong) — CNN got it backwards (pos is actually neg, or vice versa)
  • Del — bad sample, remove from training set

Columns & Filters

  • Label: pos = cursor was here, neg = no cursor at this position
  • Type: cursor shape when captured (arrow, hand, I-beam) — only from Claude Vision samples
  • Source: how the patch was collected:
    motion_track — from live tracking loop
    claude_vision — Vision-confirmed position
    ground_truth — manually verified
  • CNN Conf: model's confidence this patch contains a cursor (0-1). Green >0.7, yellow 0.3-0.7, red <0.3
  • YOLO: YOLO detection confidence (blue bar). Enriched from context crops or loss event frames
  • Priority: review order — Needs Review (-1) > CNN Disagrees (0) > confusing (1) > uncertain (2) > Vision (3) > easy (4) > reviewed (99)

Feature Tags (right columns)

Tags are independent — a sample can be "ok" AND "confusing" AND "partial" simultaneously. Click a chip to set it, click again to clear. Saves instantly.
  • quality — ok / wrong / unsure (your judgment of the label)
  • confusing — yes / no (would a human struggle to identify the cursor here?)
  • cursor_type — arrow / hand / ibeam / busy / crosshair / move
  • visibility — full / partial / hidden / offscreen
  • background — clean / noisy / animated / textured
New columns appear automatically when you tag with custom keys via the API.
